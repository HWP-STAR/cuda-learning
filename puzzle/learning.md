第一个参数：grid 尺寸（有多少个 block）

dim3 定义线程维度，默认是一维度

nvcc 并没有替代 g++/gcc，而是指挥它们。它负责处理 CUDA 特有的语法和 GPU 架构，而把标准的 C++ 代码编译工作“外包”给了你系统里现成的 GNU 编译器

每个SM中有多个block,一个 block 最多 1024 个线程
可以把它想象成一个只有 2048 个座位的报告厅（SM），虽然有32 个入口（Block 上限），但每个入口放进来的人（线程）总数加起来，绝对不能超过 2048 个座位。
**block和线程分离**
Block 是“软件概念”：它是一组线程的集合，是程序员在代码里划分的工作小组。一个 Block 里的线程可以共享同一个 SM 上的共享内存（Shared Memory），并能进行同步（__syncthreads）。

SM 是“硬件实体”：它才是真正装着 CUDA Core、Tensor Core、寄存器堆（Register File）、共享内存/L1 缓存的“芯片上的工厂”

## 为每个线程计算一个全局唯一的编号
blockDim.x ，取值是固定的
一个 block 里有多少个线程（block 的尺寸）

blockIdx.x 取值变化 0~2等，，threadIdx.x 取值变化 0~3等。
i = blockIdx.x * blockDim.x + threadIdx.x    // 行方向全局编号
j = blockIdx.y * blockDim.y + threadIdx.y    // 列方向全局编号

线程 = 一段代码的一次独立执行
线程是"执行单元"

## 共享内存
同一 block 的线程可以读写同一块共享内存，互相通信
目的：提高速度
先搬到共享内存，再从共享内存读
全局内存（慢，大）  →  共享内存（快，小）  →  各线程寄存器
     搬一次              反复读很多次

越界读全局内存，可能写入垃圾数据

CPU 的单线程思维：
一个执行流：i = 0 → 做事 → i 变 1 → 做事 → i 变 2 → ...
CUDA 是：
线程 T0：i = 0×4+0 = 0  → 做事（只做一次）
线程 T1：i = 0×4+1 = 1  → 做事（只做一次）
线程 T2：i = 0×4+2 = 2  → 做事（只做一次）
线程 T3：i = 0×4+3 = 3  → 做事（只做一次）

每个线程执行一次完整的 __global__ 函数
    // 第 1 行：算自己的编号，所以算出编号是必要的
    int i = blockIdx.x * blockDim.x + threadIdx.x;

    // 第 2 行：用自己的编号做事
    out[i] = i * 10;

没有复用时，共享内存毫无优势。
__syncthreads();等所有线程做完后进行下一步
共享内存优势：在共享内存里读和处理数据快
